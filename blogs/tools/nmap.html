NMAP Port Scanning Deep Dive

What actually happens behind the scenes when Nmap reports a port as open, closed or filtered.

I have been using Nmap for Vulnerability Disclosure Programs and CTFs, only considering the final output and never bothering about the underlying workings. However, I have a strong desire to break down the abstractions and learn about what goes on behind the scenes.

So, I learnt about behind the scenes working of Nmap port scanning and simplified it in my blog so that even beginners with basic networking knowledge can understand.

Nmap is used to scan the ports and find whether the ports are open | closed | filtered. Nmap can be also used for host discovery, OS and Versions detection. But, in this blog, we will be focusing only about Port Scanning.

Nmap has many command-line switches for scanning the ports. Most commonly used three switches for port scanning are

  1. -sT : TCP scans
  2. -sS : SYN scans
  3. -sU : UDP scans
nmap -sT <ip address> # TCP Scan
nmap -sS <ip address> # SYN Scan
nmap -sU <ip address> # UDP Scan

TCP Scan (-sT)

Transmission Control Protocol (TCP) is connection-oriented protocol. It performs three-way handshake to establish a connection with the target server. Switch used for TCP Scan in Nmap is -sT.

If Nmap sends TCP request with SYN flag to an open port, the target server responds with ACK/SYN flag to the terminal and our terminal responds to the server with the ACK flag. After connecting to the desired port, NMAP establishes that the port is open.

If Nmap sends a TCP SYN flag to a closed port, the target server will respond with the RST flag and Nmap will establish that the port is closed.

There is an another condition where the Nmap results shows that the port is filtered. This happens when the port is behind a firewall. Nmap sends the TCP SYN flag and firewall drops it. Nmap doesn’t receive any response from the target and establish the port as filtered.

SYN Scan (-sS)

Synchronize (SYN) Scan works similar to TCP Scan but with slight differences. SYN Scan is also referred to as “Half-open scan” or “Stealth Scan”. Switch used for SYN Scan is -sS.

In case of opened ports, initially, Nmap sends the TCP SYN flag to the target like a normal three-way handshake. But once it receives the ACK/SYN flag from the target, client sends the RST flag to the target than sending the ACK flag.

Since the connection is not established in this case due to incompletion of three-way handshake, SYN Scans are not logged by the applications.

In case of scanning a closed or filtered ports, SYN Scan is similar to TCP Scan. Closed ports sends the RST flag and if port is filtered by firewall, then firewall drops the incoming TCP SYN packet.

UDP Scan (-sU)

User Datagram Protocol (UDP) is a connectionless protocol. UDP Scan doesn’t perform any three-way handshakes to establish any connection. Switch used for Nmap UDP Scan is -sU.

Nmap sends the UDP packet to the target server and there will be no response from the target. Nmap refers the port as open | filtered for this sequence.

When the port is closed, target responds with ICMP(ping) packet containing a message “Port is Unreachable”.

To wrap up, Nmap is truly a fantastic tool for anyone who wants to dive deep into network mapping and port scanning. I hope you might get an idea what would have happened in background when you get Nmap results after scanning a port.
